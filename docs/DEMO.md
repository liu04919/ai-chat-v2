# 桌面演示脚本

目标是用约 8–10 分钟讲清“能使用，也能解释实现”。下面是演示操作与验收点，不是本轮已执行的测试记录。模型延迟不稳定，超时就讲已验证的边界，不临时修改参数或无限重试。

## 提前准备

- 按 [README](../README.md) 启动本地 Web、Worker、数据库、Redis；服务器演示则先按[部署说明](../deploy/README.md)打开 SSH 隧道，访问 `http://localhost:3001`。它不是任何人都能打开的公网演示站。
- 使用演示专用账户，不展示个人聊天、密钥、`.env` 或控制台令牌页。配置与浏览器实际 Origin 对应的 R2 CORS。
- 创建“演示资料”知识库，上传 [demo/knowledge.md](demo/knowledge.md)，等文档 ready。它是虚构资料，不是质量评测数据集。
- 准备一个已有较长历史的演示会话；无需为演示消耗大量模型额度。另留一个空会话用来展示切换。
- 提前确认一次普通问答、RAG 和图片渠道可用；这些操作会消耗模型或存储额度。第三方 MCP 不可用时不把它作为必演项。

## 1. 普通对话与长列表（约 1 分钟）

关闭知识库与联网搜索，发送：

> 请用一个 TypeScript 小例子解释防抖与节流，再用表格比较适用场景。

观察正文流式更新、Markdown 表格和代码块；在较长历史会话中向上滚动，确认不会被新输出强行拉回底部。

讲解重点：Query 管历史页，Zustand 管活跃输出；动态高度虚拟列表减少挂载，服务端增量合并和前端按帧更新减少高频提交。不要现场口述未经测量的提升百分比。

## 2. 切换与刷新恢复（约 2 分钟）

发送一个足够长、但不刻意追求极长输出的问题，例如：

> 分 12 个小节说明浏览器从输入网址到渲染页面的过程，每节包含一个排查思路。

在输出尚未结束时切到另一个会话，再回来；随后在仍生成时刷新。若回复已经完成，只能证明数据库历史恢复，需要另一次活跃生成才能观察流回放。

验收点：不出现重复拼字、两份助手回复，已有内容不凭空消失。切换回来可用缓存游标；整页刷新没有内存投影，需要从头回放仍在运行任务的事件。两者都不应因为恢复展示而新建一次生成。

可选断网演示：确认 SSE 已建立后，短暂关闭浏览器网络再恢复，观察同一个 EventSource 自动重连。不要用“离开路由后新建连接”冒充原生断网重连，也不要为此停止服务器或 Redis。

## 3. 停止与历史接管（约 1 分钟）

在已有文字输出后点击停止，等待状态同步，再刷新。应保留已经生成的内容；继续发送问题应正常开始下一轮。完全没有输出就停止时，不要求出现空助手气泡。

如果有已保存的助手消息，展示重新生成；无输出失败没有重新生成按钮，可复制问题重新发送。现场不必故意破坏渠道或密钥来制造失败。

## 4. 知识库问答与引用（约 2 分钟）

选择“演示资料”，关闭其他工具，发送：

> 青禾实验室的访客码能用多久？如果周五 17:30 到访，接待处还开放吗？请依据资料回答并给出引用。

期望资料依据：访客码签发后 36 小时有效；工作日 09:00–17:00 接待，因此周五 17:30 已结束常规接待。打开引用检查对应原文，再刷新检查引用仍存在。

随后问：

> 资料里有停车费标准吗？没有就说明未找到，不要猜。

资料未提供停车收费。模型应承认证据不足；如果编造，要如实标记为失败，不能因为有引用编号就判定回答正确。是否追加检索由模型决定，不把三次调用上限讲成每次都会搜三遍。

## 5. 图片或分享二选一（约 1–2 分钟）

图片：进入图片模式，发送“白色背景，中央一个蓝色圆形，无文字”，生成后再要求“保持构图，把蓝色圆形改为橙色”。检查大图预览与刷新后恢复。渠道慢时跳过等待，事先保留的成功记录要说明是历史结果。

分享：对一个已经结束的演示会话创建分享，在无登录窗口打开，确认它是只读快照；撤销分享，再刷新验证入口失效。使用 SSH 隧道部署时，无登录窗口也必须能访问同一台电脑的隧道地址，不能把 localhost 链接发送给异地面试官。

## 6. 最后用代码收束（约 1 分钟）

打开 [generation-event-buffer.ts](../apps/web/src/components/chat/generation/generation-event-buffer.ts) 和 [projection store](../apps/web/src/components/chat/generation/generation-projection-store.ts)，解释为什么“内容和游标必须一起提交”。比逐个介绍所有页面更能体现设计思考。

如被问上线方式，展示仓库 Actions 记录和[源码发布流程](../deploy/CI_CD.md)：CI 验证 → 上传源码 → 服务器构建 → 迁移与健康检查；推送 main 只触发 CI，Deploy 手动触发，不是每次 push 自动上线。

## 收尾检查

- 记录实际成功、失败及跳过项；不要把本脚本当成验收报告。
- 撤销演示分享。只删除明确属于演示的会话、知识库与文件，不清空整库。
- 模型超时、网络中断、资料答错分别记录：它们不是同一种故障。
- 备用录屏标明录制时间与环境，不当作实时演示。摘要压缩需要大上下文，面试时讲代码与测试边界即可，不现场烧 token 触发。
